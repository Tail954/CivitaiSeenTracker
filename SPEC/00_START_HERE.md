# Codex作業入口（必読・軽量）

## 目的と最重要ルール
CivitaiSeenTracker に「カレンダーで指定した日付に一致するモデルカードのみを表示する」機能を統合する。**最初に既存スクリプトを挙動変更なしでリファクタリングし、検証・独立コミットしてから実装する**。単体ユーザースクリプトとしての配布を維持する。

- 元リポジトリ: https://github.com/Tail954/CivitaiSeenTracker
- 現状の入口ファイル: `civitai-seen-tracker.user.js`（作業時に実リポジトリを確認する）。
- 対象: `https://civitai.com/models` と `https://civitai.red/models` のモデル一覧。その他ページへの副作用は禁止。
- 安全優先: 既存の閲覧履歴 `civitai_seen_models` を消去・破壊しない。非表示のカードを閲覧済みにしない。
- 日付の初期値は**今日（JST）**、単日指定、更新日モード、フィルターON。詳細は `SPEC.md`。
- 更新日とは「選択した日に作成されたモデルバージョンが1つでもある」。既存説明文の編集は含まない。
- 原則、条件不一致カードを完全非表示。無限スクロール等に修正不能な競合がある場合に限り、薄く残す方式にフォールバックし、根拠を報告する。
- 実環境を検証できない事項は未検証と明記。憶測で合格にしない。

## 最小限の読み込みルート
**全員がSPEC全体を読み込む必要はない。** `01_ROLE_ROUTER.md` に担当別のファイル・節を記載。順序は **Sol(Phase 0) → Luna(Phase 1–2) → Sol(統合/Phase 3) → Astra(監査/判定) → Sol(修正・提出)**。複数Agentが同じファイルに同時変更を加えない。

## 開始指示
まず `01_ROLE_ROUTER.md` を開き、担当を確認する。実際の作業開始前にベースラインのコミットID、動作の現状、テスト可能な環境を記録する。段階ごとに `HANDOFF.md` を更新し、合格ゲートを満たさない限り次段階に進まない。
