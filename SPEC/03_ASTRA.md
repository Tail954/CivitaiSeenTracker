# Astra担当タスク（設計・コードレビュー / 採否判定）

## 読む範囲
`00_START_HERE.md`, `01_ROLE_ROUTER.md`, `HANDOFF.md`、レビュー対象の `git diff` とテスト結果。Phase 0は `SPEC.md` §2, §6.1, §7。最終段階は §3–§7。全仕様・全コードの再読み込みは必要なときだけ。

## Phase 0ゲート（Astra-A）
- 原則としてコードを変更せずレビューする。挙動変更が混入していないか、保存キー・データ互換性、既読マークのスクロール発火、ジャンプ、SPA、`.com`/`.red` を確認。
- テストの不足と実機未検証を切り分ける。重大問題はブロッカーとして列挙し、Solへ返す。
- 完了判定は PASS / BLOCKED / CONDITIONAL と証拠を明記。PASS以前に日付機能を統合しない。

## 最終ゲート（Astra-B）
- 更新日が**該当日の任意バージョン作成**か確認（最新バージョンだけの判定は不可）。JST境界、範囲選択、今日既定値を確認。
- 日付未取得/取得失敗が「不一致」と混同されていないか。
- 非表示カードが既読にならないこと、既存履歴が保存されること、フィルターOFFで完全復元すること。
- MutationObserverによる再帰ループ、イベント多重登録、キャッシュ誤判定、429時のリトライ嵐、無限スクロール停止を重点確認。
- 完全非表示が安全な場合のみ採用を承認。再現性のある重大競合が残るなら薄表示フォールバックを勧告（視覚的にSeenTrackerの既読表示と区別）。
- 検証不能な項目をPASSにせず CONDITIONAL として残す。

## レビュー提出書式
`ゲート / 判定 / 致命的問題 / 高・中・低優先度指摘（ファイル・行）/ 必須追加テスト / 完全非表示採否 / 未検証事項` を `HANDOFF.md` に短く追記する。
