# CivitaiSeenTracker カレンダー日付フィルター統合仕様書 v1.0

- Status: 実装指示用／実ブラウザでの動作は未検証
- 対象: https://github.com/Tail954/CivitaiSeenTracker
- 入口: `00_START_HERE.md`、分担: `01_ROLE_ROUTER.md`
- 仕様変更は独断で行わず、未確定事項と理由を `HANDOFF.md` に記載。

## §1. 目的・適用範囲
日々のCivitaiモデル一覧で、今日・昨日・任意の日付にモデルバージョンが作成されたモデルだけを、Civitaiの**標準モデルカード表示のまま**閲覧できること。アプリの独立画面は作らない。既存検索・ソート・モデルタイプ・タグ等の機能は維持。サイトで**読み込み済みのカードのみ**が絞り込み対象であり、サイト全体の全件検索は行わない。

対応ページは `civitai.com/models` と `civitai.red/models` を主対象とする。パス下位URLやクエリはサイト実装を確認して対象化する。ユーザー個別のモデル詳細などの他ページにフィルターを適用しない。Chrome＋Tampermonkey想定。サイトDOM/APIの違いは事前検証し、片方に機能が無い場合は安全に無効化・明示する。

**非目標:** 過去全モデル網羅検索、サイトAPIの検索クエリ改変、サーバーへの履歴送信、モデル説明文編集の追跡、独立Webアプリ化。

## §2. Phase 0 — 新機能追加前のリファクタリング【最初に実施・独立完了必須】
### 2.1 ベースライン
作業時点のリポジトリコミットIDと現行ユーザースクリプト名を確認する。旧スクリプトの動作をREADMEとコードから洗い出し、必要に応じて実ブラウザで記録。既読判定のタイミング・グレーアウト・ホバー復元・スクロールジャンプ/中断・無限スクロール・SPA遷移・保存データの仕様を回帰テストで固定する。

### 2.2 対象責務
(1) カード/モデルID検出、(2) MutationObserverと追加読み込み、(3) IntersectionObserverと閲覧登録、(4) ページ遷移ライフサイクル、(5) UI・CSS、(6) スクロール/ジャンプ、(7) 設定・永続データの責務を明確化し、二重初期化・重複イベント処理を防ぐ。単一配布ファイルを維持できる構成にする。無理な大規模フレームワーク導入は禁止。

### 2.3 不変条件
- Phase 0では日付フィルターを追加しない。外部に見える既存機能の挙動変更を避ける。
- `civitai_seen_models` とその格納形式との互換性を壊さず、読み込み時に全消去しない。ドメイン別localStorage等の実態はコード確認する。
- モデル詳細ページなど現状非対象の画面への新たな効果を作らない。
- リファクタリング専用コミットを作成し、AstraのPhase 0ゲートに合格するまでPhase 1へ進まない。

## §3. UI・状態・操作
### 3.1 UI
Civitai画面の既存操作を覆わない小さなカレンダー起動ボタン（例: 右下既存ジャンプボタン付近）と開閉パネル。キーボード操作・フォーカス移動・スクリーンリーダーラベルへの配慮を行う。開閉だけではフィルター状態を変えない。ボタンまたはパネルに選択日/状態が識別できる短い表示を置く。

### 3.2 初期値・永続化
- フィルター: ON、日付タイプ: 更新日、選択方式: 単日、選択日: **ページを開いた時点の今日（JST）**。
- 今日・昨日ボタン、前日/翌日操作を設ける。日付はカレンダーでクリック選択し、変更後ただちに適用。
- 範囲指定は通常隠すトグルで有効化。ON時はカレンダーで開始日→終了日の順に選ぶ（UI実装上2つのカレンダーでも可。ただし普段の単日操作を煩雑にしない）。開始日・終了日を含む。逆転選択は正規化するか、理由がわかるエラーを出して適用しない。
- 同じJST日付中のページ再読込では選択した日付・モード・範囲・ON/OFFを保持する。新しいJST日に**新規ページロード**したら選択日を今日に戻し、範囲選択は解除（ON/OFFと日付タイプは保存値を維持）。ページを開いたまま午前0時を越しても現在の選択を勝手に変更しない。
- 日付フィルターOFFで全フィルター状態を解除し、元のカード表示を完全復元。ONで選択条件を再適用。
- 設定は既存閲覧履歴と**別キー**で保存。`.com` と `.red` 間の設定同期は要求しない。両ドメインで同じデフォルト・仕様とする。

### 3.3 状態表示
`検出済み/表示中/判定待ち/判定失敗` 件数を、**読み込み済みカードに限る**ことが分かる表現で示す。エラーやAPI制限時は簡潔に状態を表示。判定が終わっていない間に「該当0件」と断定しない。大量トーストや過剰なログを発生させない。

## §4. 日付の意味・比較
### 4.1 更新日（デフォルト）
**選択日（または範囲）に作成されたモデルバージョンが1つでも存在すれば一致。** 選択日以降に別バージョンが作成されても、過去の一致は有効。最新バージョンの作成日だけで比較する実装は不可。モデル本文の編集のみ・既存バージョン編集のみの履歴は原則含めない。

### 4.2 登録日
取得できるモデルバージョンの中で最古の `createdAt` を代替的登録日として使用する。これはモデル本体の初公開日時そのものとは限らない。バージョン列挙が不完全な場合は最古を確定できないため、登録日モードは**未判定**とし、必要なら詳細APIで完全性を確認する。

### 4.3 JSTの境界
APIの時刻にタイムゾーンがある場合はJSTへ正しく変換。単日はその日の00:00:00.000以上、翌日00:00:00.000未満。範囲は開始日00:00以上、終了日の翌日00:00未満。UTCとJSTの境界前後をテストする。未来日も選択可だが通常は一致なし。

### 4.4 モデル判定状態
`matching / nonmatching / pending / unknown(error or incomplete)` を区別する。`unknown`は一致しないことの証拠ではない。非表示にするのは確定した `nonmatching` のみ。待機/失敗はカードを残し、ステータス表示で区別。待機中カードをSeenTrackerの新規閲覧登録対象にしない。

## §5. 取得・フィルター実装・制限
### 5.1 日付データ取得
(1) サイトが既に保持するモデル/全バージョンの日付情報が**十分・完全と検証できるなら**利用、(2) 有効なキャッシュ、(3) モデルIDによる公開詳細API（例: `/api/v1/models/{id}`）。一覧断片に含まれる最新バージョンの日時だけで更新履歴方式を満たすと誤認しない。不完全データはAPIで補完。API通信先・認証・CORS/Tampermonkeyの権限は現行動作を実証してから決定する。

### 5.2 APIとキャッシュの負荷対策
同一モデルIDの取得を重複させず、同時要求数は原則2程度から開始。キャッシュTTLは暫定24時間だが、今日/昨日の**最新バージョンの追加**を見落とさないよう、直近日付用には短いTTL・手動再取得などの鮮度戦略を必須とする。詳細API結果のバージョン一覧が十分か検証する。HTTP 429ではバックオフ・一時停止し、無制限リトライ禁止。403/ネットワーク障害時はunknownで可視維持。フィルターOFF/ページ離脱では新しい不要リクエストを開始しない。

### 5.3 DOM絞り込み
既存サイトの検索・カード・無限スクロールを乗っ取らない。モデルIDをカード内のリンク等から抽出し、一致しない**判定済み**カードのみ非表示にする。DOM要素自体の削除、既存モデルの内容書換えは禁止。新規カード追加・SPA遷移・サイト側の再レンダリング時にも安全に再判定。元のスタイルはフィルターOFFで確実に復元する。Civitaiのカード構造やDOM selectorは実環境で確認し、ドメイン差分を分離する。

### 5.4 完全非表示とフォールバック
第一候補は `display:none` 相当の完全非表示。ただし大量除外が無限スクロール/レイアウト/ジャンプ/既読判定を壊すなら原因調査・安全な対策を優先する。それでも重大な競合が解消できない、もしくは過剰な自動読み込み・API要求が必要になる場合は**薄く表示して残す**方式に切り替え、ユーザーへ理由を報告する。薄表示は閲覧済みのグレーアウトと混同させない（ラベル・枠等を検討）。フォールバック時も日付不一致モデルのクリック可能性・意味を明示する。どちらでも既存カードのDOM削除禁止。

## §6. SeenTracker統合・テスト
### 6.1 Phase 0回帰テスト
対象: 既読付与の条件・タイミング、グレーアウト、ホバー復元、ジャンプの開始/途中キャンセル/終端、無限スクロール、SPA遷移、`civitai_seen_models` 読書き互換性、両ドメイン。自動テストで不可能な実ブラウザ項目を別記。

### 6.2 新機能と競合テスト
- 日付: 今日/昨日/任意日/範囲・逆転・両端、JST日付境界、同日複数バージョン、過去日バージョンと新日バージョンの併存。
- UI: 単日初期・新日リロード/同日リロード/開きっぱなし跨日、切替、OFF/ON復元、既存ボタン干渉なし。
- API: 重複排除、キャッシュの鮮度、429/403/失敗/不完全なモデルデータ、遅延応答後の選択変更、フィルター解除後の応答。
- DOM: 追加読み込み、再描画、SPA遷移、リスト切替、監視ループなし、Listener/Observer多重登録なし。
- **閲覧記録:** フィルターで非表示・取得待ちのモデルは閲覧済みにならない。一致モデルは従来どおり記録し、フィルターOFFで従来動作へ戻る。既存閲覧履歴は一切消さない。
- **自動ジャンプ:** フィルターON時は新規ジャンプ禁止。ジャンプ中ONへ切替なら安全にキャンセル。OFF後は従来動作。
- **無限スクロール:** 多数の不一致カードで停止・無限ループ・過剰フェッチ・極端な負荷が生じないこと。『追加読み込みなしで見つかる全モデルを表示する』保証はしない。
- `.com` / `.red` 双方で動作確認できない場合は、未確認側を「未検証」と記載し、動作保証しない。

### 6.3 判定基準
既存機能回帰なし、保存履歴保全、既読誤登録なし、フィルターOFFで復元、日付の意味が正しい、APIに過剰負荷をかけない。動作を実際に試していない試験は未実施と明記。完全非表示に重大な競合が残る場合は §5.4に従い薄表示へ変更して再テスト。

## §8. 納品と受入条件
成果物: Tampermonkeyインストール可能なスクリプト（既存のアップデート経路を極力維持）、新機能のREADME、テストコード/確認記録、リファクタリング/新機能/統合の段階別コミット、`HANDOFF.md` に含むレビュー判定・完全非表示方式採否と根拠・残課題。

最終受入の必須項目:
- 既存閲覧履歴が保持され、従来の閲覧機能が機能する。
- 既定で「今日（JST）、更新日、単日、ON」が適用される。
- 「昨日」、任意日、前/翌日、範囲指定、登録日切替、OFFが動作する。
- 更新日は対象範囲内の**任意のバージョン作成日**で一致判定する。
- 不一致のみフィルターで除外し、pending/unknownは誤除外・誤既読にならない。
- SPA/追加読み込み・API失敗時に壊れず、ジャンプ排他が成立する。
- 完全非表示か薄表示かの最終選択とその検証証拠が残る。
